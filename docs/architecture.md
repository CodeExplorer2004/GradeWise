# GradeWise 架构基线

## 当前边界

GradeWise 当前面向单校试运行，已交付登录、四角色 RBAC、模拟成绩、智能问数、自动 ECharts 配置、数据看板、P1 学情洞察/同步报告，以及 P2 语音输入、透明风险估计、浏览器提醒、多源导入、MCP SVG 渲染和异步任务。

## 角色与数据范围

| 角色 | 数据范围 |
| --- | --- |
| 学生 | 本人 |
| 任课教师 | 所授班级与科目 |
| 班主任 | 所管理班级全部科目 |
| 教务管理员 | 当前学校 |

权限由服务端身份上下文注入，模型不能扩大范围。

任课教师范围按 `teacher_id + class_id + subject_id + academic_year` 联合约束；班主任按其管理班级和学年约束全部科目。看板直接展示解析后的权限范围，避免仅从记录内容猜测权限。

分析范围与账号权限彼此独立：账号决定最大可见边界，学年、年级、届别、学期、考试类型、班级、科目和考试筛选只能在该边界内收窄。筛选值由授权后的 `score_facts` 返回，并在每个统计接口再次校验。管理员可做学校到年级/班级下钻；其他角色只显示与自身职责有关的筛选项。

跨年度口径分为两类：固定 `cohort_year` 查看同一届学生的纵向变化，固定 `grade_level` 查看同一年级的跨届变化。选择多个学年或多个年级时，系统隐藏不宜直接混合的原始学科均分、单场考试趋势和最近考试分布，改用标准化得分率/及格率进行学年或年级比较。

## 智能问数链路

```text
当前分析范围（可选） + 用户问题
  -> Orchestrator（意图路由，不持有数据库或画图工具）
  -> Schema Resolver SubAgent
  -> SQL Generator SubAgent
  -> 服务端追加学年/年级等分析条件
  -> 确定性 SQL AST 安全门
  -> Security Auditor SubAgent（仅解释风险，不参与放行）
  -> 只读 SQL Executor
  -> Visualization SubAgent
  -> Orchestrator 汇总
```

六个同步子智能体和两个 `AsyncSubAgent` 注册到 Deep Agents。核心问数路径由 LangGraph 固定边编排；SQL 放行只取决于确定性规则与数据库权限。

## P1 洞察与报告链路

```text
服务端角色范围
  -> 确定性统计 SQL（分布、z-score 异常、同科波动、最新不及格）
  -> 姓名与内部 ID 脱敏为带密钥的 HMAC 引用
  -> Warning Analyst SubAgent（只解释证据）
  -> Report Writer SubAgent（报告与 AI 评语）
  -> 服务端固定报告类型与权限边界
```

预警 Agent 不参与判定，模型不能新增预警记录。

## P2 风险与数据链路

```text
服务端 RBAC 范围
  -> 确定性特征（最近成绩、未及格比例、首末趋势、标准差）
  -> transparent-rule-v1 风险分数与原因
  -> 教务可持久化 risk_snapshots
  -> 浏览器通知 / 脱敏后交给批量预警 Agent 解释
```

风险分数只用于教学关注排序，不作能力判断。导入只允许教务账号，通过 CSV/XLSX/JSON 解析、Unicode 标准化、校内实体匹配、0 至科目满分边界、文件内去重和 `import_batches` 审计后写入。

成绩分布不统计跨考试、跨科目的成绩人次，而是取当前权限范围内最近一次考试，先按学生计算其可见科目均分，再按分数段统计人数。学情关注首页只展示摘要，完整记录通过按类型分页接口读取。

## SQL 安全不变量

1. 仅允许一条 `SELECT`。
2. 仅允许访问 `score_facts` 分析视图。
3. 拒绝注释、堆叠语句、DDL、DML 和危险函数。
4. 服务器按角色注入 `student_id`、授课关系、班级或 `school_id` 范围。
5. 参数化执行，设置只读事务、超时和最大返回行数。
6. LLM 审计结果只用于解释和规则优化，不能批准执行。

## 异步与图表服务

问数与单份报告保持同步。批量报告和批量预警通过独立 `agent-worker` 的 Agent Protocol 执行，后端只返回任务 ID，并以 Redis 绑定任务所有者；支持状态查询、更新和取消。输入证据由服务端按 RBAC 收集并脱敏，客户端不能自行提交证据。

图表导出通过独立 `chart-mcp` 服务完成。后端和 MCP 服务分别执行 ECharts 白名单校验，拒绝 formatter、renderItem、外部 URL 和未知系列，再以 SSR 方式渲染 SVG。服务仅暴露于 Compose 内网，并使用服务令牌认证。

当前 Agent Server 是官方内存开发运行时，容器和协议边界已经独立，但不具备生产持久性。正式部署必须切换到具有持久化、鉴权、重试和可观测性的生产 Agent Server。
